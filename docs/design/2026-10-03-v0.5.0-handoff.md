# Handoff spec: v0.5.0 "routing axes", start of the release

*A handoff spec is complete when the receiving tier can execute without asking the sending tier anything and without re-deriving any decision.*

Standing escalation clause: if the work turns out to fail the receiving
lane's routing test, stop and hand back early with what was learned: an
early return is cheap; pushing through is not.

- Scale: meso (session → fresh session)
- From lane: flagship (the 2026-10-03 session: v0.4.0 release, brainstorms, spec) → To lane: **per item, below**. Route each item when you pick it up; most are not flagship work.
- Date: 2026-10-03 · Playbook items: W14, W15, W16 (+ issues below)

## Goal

Ship **v0.5.0**: lanes become **classes of work** (pathfinder, navigator,
builder, keeper) scored by three questions and re-scored at every boundary;

exists for people who only want the essentials. Release through the

## Decisions already made (do not re-derive)

**Routing (#25, spec):**
- A lane is a **class of work**, not a model tier. Tier is the model's rank;
  the class → tier mapping is the **operator's**, set in their playbook. The
  method ships classes, never a default mapping.
- Three questions: **new ground** (no precedent *in the project*, or
  crossing domains), **consequence** (expensive, built upon, or irreversible),
  **verification** (checking it means redoing it). **Count the yeses**
  (AND, not OR): 3 → pathfinder, 2 → navigator, 1 → builder, 0 → keeper.
- **Veto:** irreversible AND unverifiable → pathfinder, whatever the count.
- **Re-score at every boundary** (Route, Dispatch, Return, Close). Passing
  down after a decision is made falls out of re-scoring; "tier inertia" is
  not re-scoring.
- Names and cards are final: pathfinder · frontier · uncharted; navigator ·
  judgment · charted; builder · build · specified; keeper · routine ·
  automatic. Labels `lane:<name>`.
- Exploration scores 2 (navigator) and is passed up by escalation when
  needed; the escalation experiment checks the pathfinder/navigator boundary.
- Effort lives in the mapping, not the class.

**The person is "operator"** (owner, 2026-10-03). "builder" is now a lane
only. The rename (#34) lands in every repo **before** `lane:builder` ships
anywhere. History rule: rename live guidance only; leave dated records,
plans, specs, ADRs, eval results and published content as written. The
owner applies the marketplace vocabulary edit personally.

**Nudges (#30):**
- tokenomics' distinct ground is **the session itself** (when to clear,
  compact or switch tier). Dispatch-level routing is already done well by
  superpowers; tokenomics must work **without** superpowers (it is
  usage-heavy).
- Delivery order: **skill text first** (zero install), then opt-in plugin
  hooks behind a `userConfig` off-switch, then a status-line recipe.
- Plugins can only **suggest**; they cannot run `/clear`, `/compact` or
  `/model`. Context % is visible only to the status line, not to hooks.
- **New (owner, 2026-10-03): when a nudge suggests clearing or compacting,
  it offers a ready-made handover** (a handoff spec / re-entry brief drafted
  from the current state). Rationale: people take an offer more readily than
  advice, and it makes clearing safe, because state is written down before
  the context is dropped (the G10 / lost-place failure).
- Nudges must be rare and right (nudge fatigue).

**Superpowers:** a short "composes with" note plus a phase mapping in
`adapters/` that reads none of superpowers' files. No live integration.
Contributing upstream only once tokenomics has its own data.

**Measurement:** cost at **API list price** (the harness's estimate),
labelled as a proxy for subscription allowance. The six provisional spend
fields are gathered in this repo only; they reach adopters in v0.5.0 only if
the data justifies them. Behavioural evals wait until W16 is implemented.

**Minimal entry (#29):** the routing questions, the handoff template and
"re-decide the tier at every boundary". The full method is what people grow
into. It lands after W16, so the names match.

**Release mechanics:** bump `plugin.json`, move `[Unreleased]` into
`## [0.5.0]`, make the README Status say `**v0.5.0**`, merge. Never tag by
hand. The README's "How work gets routed" section and its opening sentence
on routing are the two places that change for v0.5.
